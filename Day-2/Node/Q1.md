1. What is HTTPS? How is it different from HTTP?

HTTP sends data in plain text. Anyone can read it.
HTTPS sends data in encrypted form, so it is safe.

Difference:

HTTP → Not secure
HTTPS → Secure (uses encryption)
HTTPS protects passwords, forms, payments

2. What is SSL/TLS? What is the SSL handshake?

SSL/TLS are security technologies that protect data between browser and server.
SSL Handshake (simple steps):
Browser asks server for secure connection
Server sends its certificate
Browser checks if certificate is trusted
Secure connection is created
Data transfer starts safely
TLS is the new version of SSL.

3. What is encryption? Symmetric vs Asymmetric encryption
Encryption means changing data into a secret format so others cannot read it.
Symmetric Encryption:
Same key to lock and unlock data
Fast
Example: secret password

Asymmetric Encryption:
Two keys: public key and private key
Public key locks, private key unlocks
Used in HTTPS

4. What are certificates? What is a Certificate Authority (CA)?
Certificates prove that a website is real and trusted.
Certificate Authority (CA) is a trusted company that issues certificates.
Examples:
Google Trust Services
DigiCert
Let’s Encrypt
Browser trusts websites because it trusts the CA.

5. Authentication vs Authorization

Authentication:Who are you?
Example: Login with username & password

Authorization:What can you do?
Example: Can you access admin page or not

6. What is session-based authentication? How does it work?

Session-based auth stores login info on the server.
Steps:
User logs in
Server creates a session
Session ID is sent to browser as cookie
Browser sends cookie in every request
Server checks session and allows access

7. What are cookies? Cookie security attributes

Cookies are small data stored in the browser.
Security attributes:
HttpOnly → JavaScript cannot access cookie
Secure → Cookie sent only on HTTPS
SameSite → Protects from fake requests
Cookies help in login, sessions, preferences.

8. What is token-based authentication? How is it different from session-based?

Token-based auth uses a token (like JWT) instead of session.

How it works:
User logs in
Server gives a token
Token is sent in every request
Server verifies token

Difference:
Session-based	Token-based
Stored on server	Stored on client
Uses cookies	Uses tokens
More server load	Better for APIs
