1.What are core modules in Node.js? Name at least 10.

Core modules are built-in modules that come with Node.js and do not need installation. They provide essential functionalities like file handling, networking, and system operations. These modules are optimized and maintained by Node.js itself.

Examples (10+):
fs, path, http, https, os, events, url, crypto, stream, buffer, timers, child_process, cluster.

2.Explain the fs module. Difference between fs and fs/promises

The fs module is used to read, write, update, and delete files. It supports both synchronous and asynchronous (callback-based) methods.
fs/promises provides the same functionality but returns Promises, making it easier to use with async/await.
fs/promises results in cleaner, more readable code and avoids callback nesting.

3.What is the path module used for?

The path module is used to handle and transform file paths in a safe, cross-platform way. It ensures compatibility between Windows and Unix systems.
It helps join paths, extract filenames, extensions, and normalize paths.

Common methods:
path.join(), path.resolve(), path.basename(), path.extname(), path.dirname().

4.Explain the EventEmitter class. How do you use it?

EventEmitter is a class from the events module used to create and handle custom events.
An object can emit events, and other parts of the app can listen to them.

Usage steps:

Extend EventEmitter
Emit events using .emit()
Listen using .on()
It is widely used in streams, servers, and async workflows.

5.Difference between on() and once() in EventEmitter

on() registers a listener that runs every time the event is emitted.
once() registers a listener that runs only one time and is automatically removed afterward.
Use on() for repeated events (like data updates).
Use once() for one-time events (like initialization or first connection).

6.How does error handling work with EventEmitters?

Errors are handled using a special error event.
If an error event is emitted and no listener is attached, Node.js will crash the process.

emitter.on("error", err => console.error(err));

Always handle error events explicitly to prevent unexpected crashes.

7.What is the cluster module? Why use it?

The cluster module allows Node.js to use multiple CPU cores by creating worker processes.
Each worker runs the same application and shares the same server port.
It improves performance and scalability for CPU-intensive or high-traffic applications by distributing load across cores.

8.What are child processes? When would you spawn one?

Child processes allow Node.js to run external commands or scripts.
They are useful when heavy tasks might block the event loop.

Use cases:

Running shell commands
CPU-heavy computations
Executing Python or other language scripts
Background jobs
Node.js provides this via the child_process module.

9.Difference between spawn, exec, and fork

spawn: Streams data, good for large outputs, efficient.
exec: Buffers entire output in memory, simpler but risky for large data.
fork: Special case of spawn used to create Node.js child processes with IPC communication.
Use:
spawn for long-running tasks
exec for small commands
fork for Node.js workers
