1.What is database scaling? Vertical vs Horizontal

Database scaling means handling more data or traffic.
Vertical scaling increases power of one server (more RAM/CPU).
Horizontal scaling adds more servers and distributes data.
Vertical is simple but limited. Horizontal is complex but scalable.

2.What is database replication? Master-slave replication

Replication means copying data to multiple servers.
In master-slave, master handles writes, slaves handle reads.
This improves read performance and provides backup if master fails.

3.What is database sharding?

Sharding splits data across multiple databases based on a key (like userId).
Each shard stores part of the data, reducing load on one database.

4.Challenges of sharding

Complex queries across shards
Data rebalancing
Joins become difficult
Transactions across shards are hard

5.What is partitioning vs sharding?

Partitioning splits data within one database.
Sharding splits data across multiple databases or servers.
Partitioning is simpler; sharding is for very large systems.

6.What is a connection pool?

A connection pool reuses database connections instead of creating new ones each time.
It improves performance and avoids connection overhead.

7.What are N+1 queries?

N+1 happens when one query fetches records and N more queries fetch related data.
Solved using joins, batch queries, or eager loading.

8.What is caching? Caching strategies

Caching stores data in memory for fast access.
Cache-aside: App checks cache firs
Write-through: Write to cache + DB
Write-back: Cache writes later to DB

9.What is the CAP theorem?

CAP says a system can only guarantee two of:
Consistency
Availability
Partition Tolerance
Distributed systems must choose trade-offs.

10.What are transactions & MVCC?

Transactions ensure ACID properties.
MVCC allows multiple versions of data so reads don’t block writes, improving concurrency.
