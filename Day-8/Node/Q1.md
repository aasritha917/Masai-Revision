1.What is a database? What are the types of databases?

A database is a place where data is stored, managed, and retrieved easily. It helps applications save information permanently. Types include SQL databases (MySQL, PostgreSQL), NoSQL databases (MongoDB, Redis), in-memory databases, graph databases, and key-value databases. Each type is used based on data structure and application needs.

2.Difference between SQL and NoSQL databases

SQL databases store data in tables with rows and columns and use structured schemas. NoSQL databases store data in documents, key-value pairs, or graphs and are more flexible. SQL supports joins and transactions strongly. NoSQL is better for large-scale, unstructured, or fast-changing data.

3.When to choose SQL vs NoSQL?

Choose SQL when data is structured, relationships are important, and transactions must be reliable (banking systems). Choose NoSQL when data is flexible, large-scale, or needs high speed and scalability (real-time apps, social media).

4.What is ACID?

ACID ensures reliable transactions:

Atomicity: Transaction completes fully or not at all
Consistency: Database remains valid
Isolation: Transactions don’t interfere
Durability: Data is saved permanently after commit

5.What is BASE?

BASE is used in NoSQL databases:
Basically Available: System always responds
Soft State: Data may change temporarily
Eventually Consistent: Data becomes consistent later
It favors performance over strict consistency.

6.What is normalization (1NF, 2NF, 3NF)?

Normalization reduces data duplication.

1NF: No repeating groups
2NF: Depends on full primary key
3NF: No dependency on non-key fields
It improves data consistency.

7.What is denormalization?

Denormalization means adding duplicate data to improve read performance. It is used when read speed is more important than storage, like dashboards or analytics systems.

8.What are database indexes?

Indexes are special data structures that make searching faster, like a book index. They improve query speed by avoiding full table scans.

9.Trade-offs of indexes

Indexes make reads faster but:
Slow down inserts/updates
Use extra memory
Too many indexes reduce performance

10.What is primary key & foreign key?

Primary key: Uniquely identifies a record
Foreign key: Connects one table to another
They help maintain relationships between tables.
