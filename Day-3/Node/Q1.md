What is JWT? Explain its structure

JWT (JSON Web Token) is a token used to securely send user information between client and server.
It has three parts:
Header – token type and algorithm
Payload – user data (id, role, etc.)
Signature – used to verify the token is not changed

2️ How does JWT authentication work?

User logs in with credentials. Server verifies them and creates a JWT. The token is sent to the client. The client sends this token in every request. Server verifies the token and allows access if it is valid.

3️ Advantages and disadvantages of JWT over sessions

Advantages:
No server storage needed
Works well for APIs
Scales easily

Disadvantages:
Cannot easily revoke tokens
Token size is bigger
Security risk if stored wrongly

4️ Where should you store JWT on client?

HttpOnly cookies (best) – safest, protects from XSS
Memory – safe but lost on refresh
localStorage (not recommended) – vulnerable to XSS attacks

5️ Access token vs Refresh token

Access token – short-lived, used for API calls
Refresh token – long-lived, used to get a new access token

6️ How do you handle JWT expiration?

Set a short expiry for access tokens. When it expires, use a refresh token to generate a new access token without asking the user to log in again.

7️ What is RBAC?

RBAC (Role-Based Access Control) gives access based on user roles like admin, user, or manager. Different roles have different permissions.

8️ How do you implement authorization in an API?

Verify the JWT first. Then check the user role or permission from the token. Allow or deny access based on the role.
